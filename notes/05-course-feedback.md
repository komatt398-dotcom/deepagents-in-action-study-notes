# 课程反馈

> 基于完整跟做 16 章、并把能力组装成单个可运行 Agent 的体验。
> 评价标准：能否让学员在真实环境里复现，而不只是"看懂"。

---

## 一、做得好的地方

### 1. 章节递进合理

从 Todo → 子 Agent → 技能 → 记忆 → 审批 → 权限 → 评分，每章只引入一个变量。这种"单变量递进"符合认知负荷，学员能清楚知道是哪一步导致了行为变化。

### 2. 强调失败关闭

评分量表那一章没有停留在"让模型自评"，而是要求调用 evidence tool 取证，并以 `result == "satisfied"` 作为接受条件。这个设计比大多数 Agent 教程严谨，也是实际生产里最容易偷懒的地方。

### 3. notebook 可执行

多数章节配了能真实运行的 notebook，不是伪代码。对"照着抄都跑不起来"的课程来说，这是明显优势。

### 4. 反复强调"完成的 todo ≠ 完成的报告"

这是真实 Agent 工程里最常见的自欺。课程多次点出"文本声明完成不是状态更新"，很有价值。

### 5. 对安全边界的处理是分层的

人工审批讲"什么时候停下来问人"，权限讲"哪些路径根本不许写"。两者互补，而不是用一句"注意安全"带过。

## 二、需要改进的地方

### 1. 缺少版本矩阵

讲义部分章节基于 deepagents 0.7.10 / 0.7.15，而模板锁定 0.7.8。直接后果：

- `CodeInterpreterMiddleware`（解释器、动态子 Agent）在当前模板里不存在；
- 学员会先怀疑自己的环境，而不是版本。

**建议**：每章开头标注"本章 API 最低版本"，并给一张"讲义版本 ↔ 模板版本"对照表。对不兼容的章节，明确给出降级方案。

### 2. 缺少平台排错章节

像下面这些问题会伪装成"我的 Agent 写错了"：

- `/threads/search` 带 `values: {}` 返回 422（`values filter is not supported yet`）；
- 旧线程长期 `busy`；
- Studio 探测 `/deploy` 返回 404；
- `[sample_graphs] skipped` 之类的无害日志。

**建议**：加一节"如何区分：是 Agent 的问题，还是平台的问题"，附最小复现命令和预期输出。

### 3. Windows 支持不足

- 跨盘符 `cd` 不切盘符，直接导致 `pytest: file or directory not found`；
- 沙箱章节依赖 Docker，Windows 上容易卡住。

**建议**：

- 预备阶段显式写 `cd /d`；
- 给一个不依赖 Docker 的沙箱替代路径（如 `LocalShellBackend`）；
- 在环境检查脚本里加一条"当前工作目录是否为目标目录"。

### 4. 案例缺少证据等级标注

Turbopuffer 的"降本 20 倍"、某些"效果提升 23.5%"都是厂商口径。课程直接引用时，没有区分"独立可验证 / 厂商披露 / 二手转述"。

这恰好是 Agent 写研究报告时最需要的能力。**建议把"证据分级"做成课程内的显式规范**，并要求报告里标注。

### 5. 缺少"从 notebook 到可部署工程"的收口

notebook 教会了单个能力，但没有讲：

- 这些能力怎么组装进一个 `build_graph()`；
- 权限与审批怎么串成完整链路；
- 怎么写不依赖模型密钥的测试；
- 怎么留 trace 和运行记录。

**建议**：在收尾阶段增加一节完整走查，从一个空目录走到可运行服务。

### 6. 提示词章节偏薄

课程花了大量篇幅讲机制，但"如何把记忆、技能、审批规则写进 system prompt 而不互相打架"讲得较少。实践中把能力说明单独成段（记忆 / 技能 / 审批 / 子 Agent 各一节），比混在一条长工作流里更有效。建议补一个提示词分层的最小模板。

### 7. 可选能力缺少"默认关闭"的约定

MCP、评分量表、异步子 Agent 都需要额外依赖或服务。课程没有明确"默认关闭、按需开启"的工程约定，学员容易在本地把所有开关打开，然后启动失败。

**建议**：统一用环境变量控制，未安装依赖时只告警不崩溃。

## 三、给后续学员的三条建议

### 1. 先跑测试，再改代码

全绿之后再动手。出问题时才能二分定位：是环境、是平台，还是自己改的那一处。

### 2. 每加一个能力，加一个脚本化测试

尤其是权限和审批，这两类最容易"看起来生效、实际没生效"。脚本化模型 + 真实图，成本很低，收益很高。

### 3. 记录环境三件套

OS、Python、框架版本。遇到 API 不存在时，先 `inspect.signature` 确认，再怀疑自己。

---

## 四、一句话总结

这是一门**机制讲得清楚、工程收口略欠**的课程。

单个能力的设计（失败关闭、权限分层、上下文隔离）质量很高；把能力装成一个可运行、可测试、可排错的系统，需要学员自己补一课。补上这一课之后，课程的价值才真正兑现。
